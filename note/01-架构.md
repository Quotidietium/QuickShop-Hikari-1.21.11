# 01 · 项目架构

> 路径缩写：`QS/` = `quickshop-bukkit/src/main/java/com/ghostchu/quickshop/`，`API/` = `quickshop-api/src/main/java/com/ghostchu/quickshop/api/`

## 1. Maven 多模块结构

```
quickshop-hikari (根聚合 pom)
├── quickshop-common        12 文件  纯工具库，无 Bukkit 依赖
│                                      QuickExecutor(6 线程池)/JsonUtil/CommonUtil/GeoUtil(镜像测速)
├── quickshop-api          177 文件  公开 API 契约层
│                                      Shop/ShopManager/EconomyProvider/40+ 自定义事件/CommandManager
├── platform/               3 文件   平台适配层
│                                      Platform 接口 → PaperPlatform 实现(命令注册/物品编解码)
├── quickshop-bukkit      357 文件  核心实现层 ★ 主体代码全在这里
├── addon/*                62 文件  14 个官方扩展模块(discount/dynmap/discordsrv/plan/...)
└── compatibility/*        52 文件  30 个第三方插件兼容桥(worldguard/towny/lands/residence/...)
```

依赖方向：`common → api → platform-interface → platform-paper → bukkit`；addon/compat 编译期只依赖 api 与 compat-common，不反向依赖 bukkit；Shade 阶段全部打进最终 fat-jar（根 pom 重定位 12 组第三方包）。

`bootstrap.Bootstrap`（Manifest 主类）只是双击 jar 时的 Swing 弹窗提示，真正入口是 plugin.yml 指定的 `QuickShopBukkit`。

## 3. 技术栈要点

- **运行时依赖不打进 jar**：libby 在 `onLoad` 阶段读 `libraries.maven` 清单，镜像测速后下载注入 classpath（QuickShopBukkit.java）。首次安装需联网，之后走本地 lib/ 缓存。
- **数据库**：EasySQL + HikariCP；MySQL 或内嵌 H2(MODE=MYSQL 兼容模式)；连接池默认 maxPoolSize=10。
- **调度**：FoliaLib 统一调度器（主线程/区域线程/异步定时三种入口），兼容 Paper 与 Folia。
- **文本**：Adventure + MiniMessage。
- **经济**：Vault 1.x / VaultUnlocked 2.x 双 provider。
- **展示物**：PacketEvents（优先）→ ProtocolLib（回退）发包虚拟物品，不做真实实体。
- **GUI**：同作者 MenuCore（net.tnemc）。
- **配置**：BoostedYAML（自动版本迁移）+ simplereloadlib（热重载）。

## 4. 运行时组件架构

`QuickShop` 类是**服务定位器核心**（单例 `QuickShop.instance` + 静态门面 `QuickShop.folia()/menu()`），聚合 40+ 管理器。核心服务：

| 服务 | 类 | 职责 |
|---|---|---|
| shopManager | SimpleShopManager | 商店 CRUD / 交易入口 / 聊天价格输入 |
| shopLoader | ShopLoader | DB→内存并行加载 |
| databaseHelper | SimpleDatabaseHelperV2 | 12 表 DAO + 版本迁移链 |
| economyLoader | EconomyLoader | 延迟 1 tick 装载 Vault 系 |
| interactionManager | QuickShopInteractionManager | 交互类型→行为映射（interaction.yml 数据驱动） |
| virtualDisplayItemManager | VirtualDisplayItemManager | 数据包假实体展示 |
| itemMatcher | 策略三选一 | QuickShop/Bukkit/Modern 物品匹配（config `matcher.work-type`） |
| textManager | SimpleTextManager | i18n + Crowdin OTA |
| permissionManager | PermissionManager | 权限检查（仅 BUKKIT provider） |

## 5. 核心域模型

### 5.1 商店继承体系

```
Shop (API 接口, 泛型 Shop<P,L>)
 └── ContainerShop (唯一实现: isLoaded/dirty/displayItem/runtimeRandomUniqueId)
ShopManager (API 接口)
 └── AbstractShopManager (内存查找表: Map<world, Map<ShopChunk, Map<Location, Shop>>>)
      └── SimpleShopManager (actionBuying/actionSelling/actionCreate/actionTrade/handleChat/deleteShop)
```

- `ContainerShop.buy()/sell()` 委托给 `SimpleTradeService`（executeBuyFromShop/executeSellToShop/preview×2 四方法门面）。
- 内存查找表配合 Guava Cache（3 分钟过期）三级查找；`getShopIncludeAttached` 处理告示牌→容器关联。
- **二级索引（2026-08-16 性能轮引入，AbstractShopManager 内）**：`shopIdLookup`（id→shop）、
  `shopsByOwner`（owner→shops，写时复制列表）、`shopRuntimeIdLookup`（runtime UUID→shop），
  与三层表同生命周期维护（注册/注销/setShopId 回填/所有权转移四处挂钩）；位置查找用
  ThreadLocal 归一化探针 + 块坐标扫描兜底。语义约束：runtime 索引仅解析「已加载」商店。

### 5.1.1 热路径缓存与快路径总览（两轮性能优化，2026-08-16）

| 缓存/快路径 | 位置 | 键→值 / 机制 | 失效/守卫 |
|---|---|---|---|
| dataIdByRecord | SimpleDatabaseHelperV2 | 记录内容 Map→data 行 id | TTL 10min；removeData/purgeIsolated/导入 |
| persistedRecordByShop | SimpleDatabaseHelperV2 | shopId→上次落库记录（不变即跳写） | 同上 + removeShop |
| dataIdByShopId | SimpleDatabaseHelperV2 | shopId→data id（指标插入免 SELECT） | 同上 + updateShop 换绑 |
| rawTemplateCache / staticComponentCache | SimpleTextManager | (locale,path)→原始模板 / 无参解析组件 | reset()（热重载）/register() 按 locale 前缀 |
| proxiedLocaleCache | SimpleTextManager | langCode→ProxiedLocale | reset() |
| DESERIALIZED_CACHE | QUserImpl | 序列化串→QUser 实例 | TTL 5min，8192 条 |
| 事件零监听器快路径 | AbstractQSEvent | 共享 HandlerList 为空则跳过 Bukkit 派发 | 监听器注册自然生效 |
| 匹配器免克隆直通 | ContainerShop.matches | 内建 QuickShop 匹配器直接传原栈（匹配器只读+内部归一） | 第三方匹配器走防御拷贝分支 |
| 匹配事件构造守卫 | QuickShopItemMatcherImpl | 零监听器不构造 ShopItemMatchEvent（免 2 克隆） | 同上 |
| 迭代器单次快照 | InventoryWrapperIterator.ofBukkitInventory | 创建时取一次 getStorageContents，next() O(1) | setCurrent 写回仍取实时数组 |
| getItemUnitSize | ShopMeta 默认方法 + ContainerShop | 零监听器时直接读 item.getAmount()（免克隆+RETRIEVE 事件） | 有监听器走完整 getItem() 路径 |
| 交易单次库存定位 | SimpleTradeService | executeBuy/Sell 定位一次，preview 与提交共享 | 公开 preview API 仍自定位 |
| 交易预检观测透出（R15） | TradeResult.observation | 预检测量（箱库存/空间、交易者库存/空间）随结果返回 | 第三方 TradeService 空观测时 action 层回退真实扫描 |
| 匹配器类型门（R15） | QuickShopItemMatcherImpl | 未命中且材料不同时免 2 次归一克隆（事件/商店 ID 覆盖仍先行） | — |
| 交易后木牌批处理 | SignUpdateWatcher | 交易成功入队（带交易者 locale），每 10 tick 至多刷一次 | shop.immediate-trade-sign-updates 可回退逐笔 |

### 5.2 事务体系（命令模式 + 补偿回滚）★ 项目精髓

经济与库存用同一套模式，**没有数据库事务/锁，全靠 LIFO 反向补偿**：

```
InventoryTransaction / EconomyTransaction (接口: commit/rollback/failSafeCommit|safeCommit)
 └── SimpleInventoryTransaction / QSEconomyTransaction
      内部: Deque<Operation> processingStack   ← 操作栈
           Operation (接口: commit()/rollback())
            ├── 库存: AddItemOperation / RemoveItemOperation (持快照)
            └── 经济: EconomyDepositOperation / EconomyWithdrawOperation (反向补偿)
```

执行纪律：每个 op 成功 → 入栈；任一失败 → LIFO 弹栈逐个 `rollback()`；库存另有 `restoreSnapshot` 兜底。

### 5.3 展示子系统

`AbstractDisplayItem` → DisplayType 配置分派：`VIRTUALITEM(2)` 当前唯一内建可用（REALITEM/ARMORSTAND/ENTITY_DISPLAY 已注释禁用）；`CUSTOM(900)` 留给第三方经 ServiceInjector 注入。VirtualDisplayItemManager 预生成 spawn/meta/velocity/destroy 四包，按 PacketEvents→ProtocolLib 择优发包。

### 5.4 交互路由（数据驱动）

12 种 InteractionType（站立/潜行 × 左/右 × 店方块/容器/告示牌）经 `interaction.yml` 映射到 6 种 InteractionBehavior（TradeInteraction 聊天提问 / TradeDirect 一组 / TradeDirectAll 全部 / TradeUI 菜单 / ControlPanelUI / ControlPanel 聊天面板）。

## 6. 数据库 schema（12 张表，版本 20）

三表分离 + 数据行去重是关键设计：

```
qs_shop_map (world,x,y,z → shop_id)   坐标索引
qs_shops    (id → data_id)            店铺壳
qs_data     (owner/item/price/type/shop_state/permissions/extra/benefit...)  实质数据 ★
```

- 写库时 `queryDataId` 按字段查重（排除 create_time），命中则复用 data id —— 多店共享同一行，省空间。
- 其余表：qs_messages(离线消息)/qs_metadata/qs_players/qs_external_cache/qs_tags/qs_log_purchase/qs_log_transaction/qs_log_changes/qs_log_others。
- 迁移链 v3→v20（v9 起每步先 fastBackup）；版本 >20 时拒绝启动防降级毁库。

## 7. 扩展点（四条通道）

1. **Bukkit ServicesManager**：`QuickShopProvider` 注册 API（QuickShop.java:437-453）。
2. **ServiceInjector 反向注入**：第三方可注册更好实现替换默认（用于 ItemMatcher / DisplayProvider）。
3. **自定义事件 40+**：全部 PRE → MAIN(可取消) → POST 三阶段。
4. **独立 jar 模块**：addon/*（功能扩展）与 compatibility/*（全部继承 `CompatibilityModule` 单基类）。

## 9. 架构总评

- **六边形倾向**：api 定义端口（Shop/Economy/Inventory/Interaction），bukkit 提供适配器，第三方可注入替代实现。
- **并发自洽但复杂**：主线程(交易) + Folia 区域线程(方块) + 虚拟线程(SQL) + work-stealing(保存/档案 IO)。
- **技术债**：SimpleShopManager/QuickShop/ContainerShop 三个巨型类（1600-2000 行级）；零测试是最大风险。

# R59 · 逻辑与稳定性审计——交易日志/历史/归档面 + 聊天事件迁移 + 长时高负载稳定性

> 第五十九轮。视角：**交易日志/历史/归档面专项**（R58 未覆盖清单首选项——58 轮从未系统审计的 DB 日志表写入/清理/查询链、qs.log 文件生命周期、历史菜单与 viewer 生命周期、日志表索引与无界增长）、**聊天事件体系迁移**（R56 残留#1 清偿：AsyncPlayerChatEvent→AsyncChatEvent + mute 门控真实化 + 消费竞态）、**长时高负载稳定性残余**（HikariCP 池参数失效、无界缓存、热重载执行器）。与 R53（菜单并发）、R54（输入面/计量）、R55（持久层）、R56（主线程/监听器/reload）、R57（附属 YAML/DB 故障）、R58（生命周期竞态/交易核心/命令面）互补。

> 方法：三个并行探查代理（日志历史归档 very thorough / 聊天面与迁移可行性 very thorough / 长时稳定性 very thorough）+ 主审逐条回源码亲验全部确认项与排除项（TNML MenuManager.addViewer/merge 行为经字节码反汇编亲验——merge 只复制 menu/page/status/chatHandler 四标量且保留旧对象在 map；easysql-hikaricp 0.4.7 重打包 HikariConfig 的池 setter 签名经 javap 亲验；Paper ChatProcessor 双事件链契约（legacy 先发、取消态显式传播进 modern）经代理对 paper 源码核实）。

## 一、修复清单（四批次 19 处 + benchmark 清偿）

### 批次一：历史查询面六处（60139e008）

1. **/qs history 与 silent 变体重复执行显示陈旧数据**：`MenuManager.addViewer` 对已存在同 UUID viewer 只调 `existing.merge(newViewer)` 且保留旧对象（字节码亲证：merge 只复制四标量、不合并 data map）；命令在主线程先 addViewer、DB 往返后才 addData——第二次执行时数据全部写入孤儿对象，菜单读到旧 viewer 永远显示上一次查询。代码库 browse/keeper 三处早有 removeViewer-then-add 先例与注释，唯两个 history 子命令漏掉。viewer 创建移入异步体数据就绪前。
2. **keeper 菜单 Transaction History 按钮打开的历史列表永远为空**：写入侧漏装 `HISTORY_DATA_RECORDS`，渲染端 `dataRecord == null` 即 continue 跳过全部条目——补 dataId 去重+批量 DataRecord 加载（对齐 SubCommand_History）。
3. **MenuViewer 无玩家退出清理**：ESC 关闭不移除（库设计保留重开状态）、TNML 无 quit 监听——每个跑过历史的玩家在 MenuManager.viewers 持有至多 1000 条记录+全部物品快照直至重启；onPlayerQuit 补 removeViewer。
4. **/qs history accessible 全服商店权限过滤在主线程**：每店克隆权限表+拼接权限日志（playerAuthorize 的 eager 字符串拼接），O(全服商店) 主线程负载；过滤移入异步体（QS 事件构造自动按线程标记 async，异步 callEvent 合法）。
5. **历史菜单翻页无效解析**：userName 的 QUser 解析在 `i < start` 跳过检查之前执行——翻到第 N 页对前 (N-1)×36 条全部做档案 IO 派发；移到跳过检查后并按 buyer UUID 记忆化。
6. **ShopHistory 空映射与损坏行防御**：owned 无店玩家 `IN ()` SQL 语法错误（query 一次+generateSummary 十二次）→ internal-error；补 query/generateSummary 两处空映射早退；行解析补 IllegalArgumentException 守卫（手改大小写 type/损坏 buyer UUID 单行跳过不中止视图）+ valueOf 大小写归一；六处 catch 文案与所属查询对齐。

### 批次二：日志保留面与数据库长时稳定六处（567197bb3）

7. **LogWatcher 轮转仅在构造器**：数月不重启的服务器 qs.log 无视 file-size 阈值无界增长；轮转提取为 rotateArchive/rotateAndReopen，run() 每次冲刷后检查大小原地轮转，重开失败降级死写入器（维持 R55 丢弃防 OOM 契约）。
8. **CalendarEvent 零监听器（挂点空转）**：新增 CalendarListener——WEEK 触发执行 MsgUtil.clean()（离线消息按设计一周过期，原仅启动清理，长 uptime 持续堆积）+ 可选自动日志清理。
9. **日志/消息表零索引**：log_others/log_changes/log_transaction/message 无任何索引——logEvent 每行写、玩家上线投递、purgelogs 按 time 删全表扫；schema 20→21 迁移 performMaintenanceIndexes（六索引逐条隔离防 partial-migration 卡死），新装经 DataTables 建表直得；顺带修 performLogPurchasesIndex 单 catch 吞后续索引（重跑撞 duplicate key 即永久跳过剩余）。
10. **新增 logging.auto-purge-days**（默认 0=关）：启用后每周自动 purgelogs 老于 N 天的行——四表此前除手动命令外无任何清理路径（长时运行无界增长）。
11. **purgelogs 尾随 purgeIsolated 失败被吞**：err 忽略照报 trim-complete（null 计数）；补 err 分支。
12. **logEvent DB 写失败仅 dev 调试输出**：DB 断连期间历史事件行全部无声消失；升级节流 warn（每分钟至多一行，不按交易速率刷屏）。

### 批次三：聊天面四处（2502f857a，R56 残留#1 清偿）

13. **AsyncChatEvent 迁移**：ChatListener 与 GuiChatInputManager 从废弃的 AsyncPlayerChatEvent 迁移（消费面仅纯文本——PlainTextComponentSerializer.serialize(message()) 逐字保持 LiteBans 前缀剥离与 trim 语义；取消态两事件契约等价，legacy 链取消显式传播进 modern）。
14. **mute 门控真实化**：两监听器原 LOWEST 在 mute/过滤插件（多为 NORMAL+）取消之前执行，isCancelled() 恒 false、`shop.ignore-cancel-chat-event` 形同虚设——被禁言玩家可经商店聊天提示照常交易/改价/删店；迁 HIGHEST 后 legacy 链与 modern 链低于 HIGHEST 的全部取消可见，门控（默认 false 保持 LiteBans 兼容语义）与 GuiChatInputManager 新增的同一门控均真实起效。
15. **GuiChatInputManager 同 tick 双消息竞态**：get()+延迟 1 tick remove 使两条消息读到同一 context、handler 双执行（改价两次/删除确认双触发仅靠幂等性兜底）；改原子摘除（remove 即 claim，落败方落空），declined handler 经 putIfAbsent 复位且不覆盖窗口期内注册的新提示；静态 instance 补 volatile。
16. **shutdown() 零调用接线**：onDisable 显式注销并清 pendingInputs，不再单独依赖 Bukkit 按插件 unregisterAll。

### 批次四：长时稳定性三处（de7d226ff）

17. **HikariCP 池参数从未生效**：database.properties 全部键值一律 addDataSourceProperty 下发 JDBC 驱动，池级键（maximumPoolSize/connectionTimeout 等）从未到达池 setter——高负载部署调池完全无效（默认 10 与配置巧合一致掩盖问题，connectionTimeout 实际 30s 而非配置 60s）；改白名单分发（新支持 leakDetectionThreshold），非数字值告警跳过，config 注释说明两类键。
18. **MarketUtils.INVENTORY_SNAPSHOTS 只增不减**：shopId 自增不复用，已删/停浏览商店条目永存（static 跨 reload）；补搭车清扫——每个完成加载批次剔除超过 10×TTL 的条目（负缓存时间戳随刷新前移、活跃条目天然免疫）。
19. **QUserImpl 静态缓存跨热重载持有死执行器**：QuickExecutor.shutdownAll 重建池后 DESERIALIZED_CACHE 命中实例仍带旧执行器，档案查找 RejectedExecutionException 最长 5 分钟；liveProfileIoExecutor() 使用时检测关停回落现行主池。

### 顺带：benchmark 模块失同步（079b3676c）

R56 删除 MarketUtils 无快照变体时未同步 MenuBench 三处调用，benchmark 模块自 R56 起不可编译（R56–R58 均未构建该模块）；基线 5 参分支改 MethodHandle 反射（当前 jar 无此方法、基线 jar 仍可测），NAME 排序补空快照（NAME 不读快照语义不变），browseGroupPipeline 补 -1 键快照条目（组统计自 R56 读预载 map，保持统计读取真实命中）。

## 二、完好不变式抽样（本轮验证通过的）

- **LogWatcher 死写入器契约（R55）不回归**：运行期轮转重开失败置 null writer，log/logLazy 丢弃不排队（既有 LogWatcherDeadWriterTest 三用例全绿维持）。
- **聊天单消费互斥保持**：ChatListener 对 pendingInput 让位（检查在先，GuiChatInputManager claim 在后）+ claim 模型下每条消息至多一个消费者；TNML 三平台 legacy HIGHEST 监听器因 awaitingChatInput 永不被 QS 置位而不参与消费（反编译核实）——迁移后双事件链上仍互斥。
- **QS 事件异步合法性**：AbstractQSEvent 构造器 `super(!Bukkit.isPrimaryThread())` 自动按调用线程标记 async——accessible 异步过滤路径的 ShopPlayerGroupEvent 等 callEvent 合法。
- **getAllShops() 线程安全**：CHM 弱一致迭代复制到新 ArrayList，异步过滤可接受。
- **getConnection 全调用方 try-with-resources/finally**（代理逐一核对 SubCommand_Debug/DataTables/SimpleDatabaseHelperV2×3/ShopHistory×8/DatabaseInfoItem/DatabaseIOUtil）。
- **批队列关停冲刷在位**：onDisable 依序 metricBatcher.flushSync(10)、dbWriteBatcher.flushSync(10)，失败 requeue 有 10000 上限+头部驱逐+告警。
- **六 Watcher start/stop 配对无叠加**（reload 先 stop 旧任务；onDisable 由 cancelAllTasks 兜底）；全部重复任务循环有 Throwable 包裹（单次异常不杀定时器）。
- **Guava 缓存全部有界**（QUserImpl 8192/5min、AbstractShopManager 1024/10min/weak、SimpleDatabaseHelperV2 三缓存、SimpleShopCache 8192/3min、FastPlayerFinder 5000/3d、PAPI 双缓存等——代理核对十余处）。
- **HikariUtil 白名单分发后驱动键语义不变**：非池级键仍走 addDataSourceProperty（cachePrepStmts 等七键不受影响）。
- **quit 清理与 TNML 兼容**：removeViewer 后 TNML close 监听 findViewer 得空 Optional 优雅 no-op（Optional 消费面核实）。
- **SQL 注入面**：日志/清理/消息全链参数化（easysql Prepared 动作）；listAllANotExistsInB 拼接仅枚举内固定表/列名。
- **qs_messages 投递语义**：flush 先取 cutoff 再读再删 `<= flushStart`，并发写不丢；删除失败仅下次登录重复投递不无限重投。
- **LogWatcher 队列死写入器丢弃**、**ShopPurger 原子门全路径释放**、**easysql addTimeCondition 方向核对**（clean/purge 均 `time <= cutoff` 无反转）。

## 三、已接受残留（带理由）

| # | 残留 | 理由 |
|---|---|---|
| 1 | qs_log_transaction 表死路径（无写入方亦无读取方；建表+清理支持它但永远零行） | 移除=破坏 DatabaseHelper API（insertTransactionRecord 在接口上）；接线=给无人读取的数据新增每笔经济事务一次 DB 写（与 R17/R20 每笔交易 DB 写批量化方向相反）；维持现状为无害死重量 |
| 2 | purgeLogsRecords 四表顺序删非原子（中途失败返回 -1，无法区分哪些表已清） | 低频管理命令；事务包裹需跨四表连接管理复杂度；逐表 try/catch 汇总为可选后续增强 |
| 3 | 历史菜单 userName 首屏可能显示 UUID（名字异步解析未完成时 getDisplay 回落） | 档案解析完成后翻页即恢复（本轮记忆化已消重复解析）；预热属增强非缺陷 |
| 4 | generateSummary 十二个查询受执行器并行度限流 | 亲验修正：supplyAsync 创建即并发启动、串行 join 仅等待非串行执行——代理原报「12 串行 RTT」不成立；menu 打开为异步背景等待，非缺陷 |
| 5 | ShopListPage/GroupedItemPage 物品名为 prettifyText 枚举名 | R58 残留#5 维持（客户端本地化物品名为独立增强项） |
| 6 | Folia region 一致性系统性方案、多服务器共享 DB 竞争、实机 E2E/浸泡 | R54–R58 连续留白维持 |
| 7 | matcherplus 模块无法本地解析 | R37 起留档既有环境问题（上游仓库不可达），本轮未触及；全模块打包 61 产物（R58 为 64，差值即 matcherplus 系） |

### 已知架构权衡（非缺陷，勿"顺手修复"）
- 库存过户成功但经济提交失败时，无自动逆向库存过户（SimpleShopManager.actionSelling），仅日志告警。这是"先库存后经济"顺序的既定权衡。
- checkTax 失败只回调 onTaxFailed，不回滚主交易（税是事后动作）。
- QSEconomyTransaction 构造器内触发事件，事件监听器若调用 amount()/toTax() 等 setter，已算好的 fromAmount/totalTax（final）不会重算——API 使用者应只用 builder 传税参。
- `to == null` 是有意的"钱消失"语义（建店费、无限商店）。

## 3. 扩展开发指南

### 3.1 新增 /qs 子命令
1. `QS/command/subcommand/` 下新建 `SubCommand_Xxx implements CommandHandler<PlayerCommandSender>`（参考 SubCommand_SilentBuy，模板极稳）。
2. 实现 `onCommand`（权限已由 SimpleCommandManager 统一检查）与 `onTabComplete`。
3. 在 `SimpleCommandManager` 构造器用 `CommandContainer.builder()` 注册。

### 3.2 新增兼容模块（compatibility/）
1. 新建模块目录：pom.xml（依赖 quickshop-api + compat-common + 目标插件 provided）+ plugin.yml（depend 目标插件、softdepend QuickShop-Hikari）。
2. `Main extends CompatibilityModule`：基类已提供 onLoad/onEnable/getShops/recordDeletion/热重载钩子，只需实现 `init()`（读配置+注册第三方监听）。
3. 集成点通常是：注册目标插件的保护检查 + 监听 ShopCreateEvent/ShopPermissionCheckEvent/ShopPurchaseEvent 做拦截。
4. 登记：根 pom.xml `<modules>` + mc-publish.yml 上传列表。
5. 参考 worldguard/Main.java（225 行，最完整范例）。注意 itemsadder 模块因外部依赖无 Maven 仓库被 CI 排除。

### 3.3 数据库 schema 变更
1. `DatabaseUpgrade` 增加版本 N→N+1 方法（内含 fastBackup）。
2. `DataTables` 枚举同步改 DDL 工厂。

4. 迁移错误会毁库——必须在 MySQL 与 H2(MODE=MYSQL) 双后端验证。

实现 `ControlComponent`：`generate(componentHolder, player)` 产出按钮（内部拼 `/qs silentbuy {runtimeUUID}` 之类 silent 命令字符串）+ `getClickType()`。参考 ShopModeComponent。

## 4. 开发纪律（违反会引入并发/资金 bug）

1. **动钱必走 QSEconomyTransaction.builder()...safeCommit()**，绝不直接调 EconomyProvider。
2. **动库存必走 SimpleInventoryTransaction.failSafeCommit()**。
3. **方块/告示牌操作必须 `QuickShop.folia().getScheduler()` 调度**（Folia 区域线程）；主线程断言用 `Util.ensureThread`。
4. **SQL 只走 sqlManager 的 executeFuture/executeAsync**（虚拟线程池），不在主线程碰数据库。
5. **属性变更走三阶段事件**（PRE→MAIN 可取消→POST），别绕过事件直改。
6. 商店写库靠 `setDirty + update()`，5 分钟 watcher 兜底，不要自己写即时 UPDATE。
7. 新增监听器继承 `AbstractQSListener`（自动热重载注册/注销）。

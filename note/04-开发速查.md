第六轮收敛扫描（Loop 25）验证为安全：pl3xmap（占位符仅受限字符集）、bluemap/squaremap（同）、util/matcher（类型+元数据对称严格匹配，无可混换漏洞）、util/updater（异常全捕获）、util/reporter（隐私审查+主线程拒绝+仅 QS 栈帧行）、util/paste（quickshop.paste 权限门控）、towny purgeShops（异步只读+regionThread 删除）、全部 compat 模式扫描（无裸 getArgs/无拼接 SQL/无非主线程 setExtra）。**该轮零新缺陷。**

此前各轮验证为**安全**的部分：SQL 全参数化（无注入面）；价格路径（actionCreate/SubCommand_Price/ShopUtil.setPrice 三处均过 PriceLimiter，默认 min=0 拦负价）；收益命令有 0<percent<100 校验且校验在事件修改之后；interactiveManager 退出/移动清理（无泄漏）；rateLimit/adventureWorkaround 用 ExpiringSet 自过期；聊天交易 TOCTOU 防护（Info.hasChanged JSON 快照比对 + shopIsNotValid 二次校验）；OngoingFeeWatcher 删店前手动余额预检；ContainerShop 全文精读（update CAS 防重入/setShopId 防重设/三阶段事件完整）；AbstractShopManager 三层查找表全并发 Map；silent 命令有全量扫描兜底与 UUID 解析防护；所有权命令均有 OWNERSHIP_TRANSFER 鉴权。

### 已知架构权衡（非缺陷，勿"顺手修复"）
- 库存过户成功但经济提交失败时，无自动逆向库存过户（SimpleShopManager.actionSelling），仅日志告警。这是"先库存后经济"顺序的既定权衡。
- checkTax 失败只回调 onTaxFailed，不回滚主交易（税是事后动作）。
- QSEconomyTransaction 构造器内触发事件，事件监听器若调用 amount()/toTax() 等 setter，已算好的 fromAmount/totalTax（final）不会重算——API 使用者应只用 builder 传税参。
- `to == null` 是有意的"钱消失"语义（建店费、无限商店）。

1. 新建模块目录：pom.xml（依赖 quickshop-api + compat-common + 目标插件 provided）+ plugin.yml（depend 目标插件、softdepend QuickShop-Hikari）。

## 4. 开发纪律（违反会引入并发/资金 bug）

1. **动钱必走 QSEconomyTransaction.builder()...safeCommit()**，绝不直接调 EconomyProvider。
2. **动库存必走 SimpleInventoryTransaction.failSafeCommit()**。
3. **方块/告示牌操作必须 `QuickShop.folia().getScheduler()` 调度**（Folia 区域线程）；主线程断言用 `Util.ensureThread`。
4. **SQL 只走 sqlManager 的 executeFuture/executeAsync**（虚拟线程池），不在主线程碰数据库。
5. **属性变更走三阶段事件**（PRE→MAIN 可取消→POST），别绕过事件直改。
6. 商店写库靠 `setDirty + update()`，5 分钟 watcher 兜底，不要自己写即时 UPDATE。
7. 新增监听器继承 `AbstractQSListener`（自动热重载注册/注销）。
8. **动缓存必想失效**：SimpleDatabaseHelperV2 三缓存（TTL 10min + 显式失效）、SimpleTextManager 三缓存（reset/register 失效）、QUser 驻留（TTL 5min）、查找表二级索引（注册/注销/setShopId/所有权转移四处维护）——新增删除/导入/换绑数据的代码路径时必须同步接失效钩子。
9. **性能改动必须过基准**：`benchmark/` 前后各 3 fork 对比（注意本机存在 ±15~45% 会话级漂移，重要结论用同批次交替测量归因，方法学见 note/report/perf）。

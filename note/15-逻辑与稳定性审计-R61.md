## 二、亲验修正

1. **恢复备份可导入性**：探查代理断言"DatabaseIOUtil.exportTables 无 sidecar→recovery 产出的备份不可导入"——对 DatabaseIOUtil 事实正确，但混淆了对象：`/qs export` 所用 TableZipCsvBackup.exportTables 一直写 sidecar。修法定为 performBackup 委托带 sidecar 的导出路径，使主备份链统一可导入。
2. **limited 插件名 qssuite-limited**：探查判定为缺陷建议改名——git 考古 2e71fd31b"change the addon-plugin name for extending old data"系上游刻意更名续旧数据，改名即孤立现有安装的 extra 数据。判定保留。
3. **本轮测试自检两误**（测试语义错误而非产品代码）：① DiscountCode.maxUsage 为 per-player 配额（跨玩家独立槽），并发烧配额回归须同玩家多线程；② apply() 配额尽返回原价（停止折扣）而非 0——两处断言修正。

## 三、完好不变式抽样

- 全库 SQL 参数化面 R60 已全量核对；本轮 importTables 新增 SQL 亦全走 PreparedStatement（DELETE/INSERT）+ 反引号白名单列，标识符不参数化的唯一例外（CREATE UNIQUE INDEX 索引名）为编译期常量。
- QSEconomyTransaction 资金保恒：单事务锁存+保恒测试（deposits==withdrawal）在新增重入/重算用例下仍绿。
- displaycontrol 新装 DDL 即唯一索引，REPLACE upsert 无竞态窗口；旧表迁移失败仅降级不阻断启动。
- addon/discount 新增测试钉住 Gson 反序列化拒绝 0%/100% 费率（防手改 data.yml 造"免费购买"码），saveToString↔fromString 往返保真。

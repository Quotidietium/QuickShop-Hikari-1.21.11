## 二、修复清单（三批次 21 处）

### 批次一：生命周期竞态与并发安全（a24a5928e）

1. **建店持久化窗口删店→DB 幽灵店**（AbstractShopManager.registerShop）：异步链（createData→createShop→setShopId→shopIdLookup 注入→createShopMap）完成时不感知删除——DB 往返期间删店后链仍注入已删商店并重插映射行（玩家已退款但店复活）。ContainerShop.isDeleted 原为 `private final boolean = false` 恒假死标志，改真实 volatile 位（Shop API 新增 isDeleted/markDeleted 默认方法）；registerShop 链 INSERT 前后两处检查（覆盖 check-后-delete 的 TOCTOU：后置检查在 map INSERT 落地后执行，volatile 实序保证删除方自带的全行 DELETE 或链内清理必居其一命中已提交行），命中即清理 shops/data/map 行且异常自包含（防误落 processCreationFail 双退款）。
2. **unregisterShop 对 shopId<=0 同步抛异常**：removeShop(-1) IllegalArgumentException 穿透删除路径（含 processCreationFail），finally 后续 unloadShop 被跳过；改为跳过 removeShop（由①链内清理兜底）。
3. **inDeletion 以 shopId 为键**：两间未落库商店（均 -1）并发删除时第二间被静默跳过（不退款不注销）；未落库分支改身份键集合 inDeletionTransient。
4. **转账 60s 窗口资产盗取**（ShopUtil.PendingTransferTask.commit）：A 发起 transferownership 后反悔（setowner 给 C/管理员改属主），B 窗口内 accept 即 setOwner(B)——B 对该店从无权限；commit 逐店校验 getOwner() 仍等于发起者，失配跳过并提示（transfer-skipped-not-owner 新键 en/zh）。
5. **playerGroup 普通HashMap**：员工/权限命令在异步档案 IO 回调 put/remove，与主线程交易许可复制、异步通知遍历、保存线程序列化并发——丢失更新/CME/结构损坏；改 ConcurrentHashMap（构造过滤 null 脏数据防整店不可加载）。
6. **QSBenefitProvider 双缺陷**：benefits HashMap 同病（改 CHM）；deserialize 无份额和守卫——绕过 add() 溢出检查的 DB 行（旧版数据/手工编辑）使每笔交易支付 amountAfterTax×sum(>1) 而仅扣 fromAmount=铸币；无效集合整体弃用回退全额归店主并告警。
7. **世界重载二级索引泄漏**（addShopToLookupTable）：Multiverse unload/load 后 ShopLoader 重注册同位置新对象，inChunk.put 覆盖但 shopsByOwner/runtimeIdLookup 不 unindex 旧对象（重复项+永不过期+同 id 双对象）；检测到不同旧占用者先 unindexShop。
8. **WorldListener.onWorldLoad 整图替换竞态**：重建 per-world 图后 put 替换，并发注册（同世界建店）在重建窗口内写入被丢弃；改为对现图原地修正 Location 的 World 引用（Location hash/equals 基于世界名，原地变更安全）。
9. **ContainerShop.add 无界循环**（refill）：忽略 addItem 溢出返回值，容器满后按剩余量逐组空转（/qs refill 20亿≈3400 万次全槽扫描冻结主线程）；读取未容纳量装满即止。

### 批次二：命令面缺陷与鉴权缺口（a888bd70b）

10. **/qs tag shops 空结果负下标**：无标签玩家 tagsCount 返回 {TOTAL_INDEX:0} 非空 map 通过 isEmpty 检查，移除 TOTAL 后空列表→totalPages=0→page 钳 0→循环 entries.get(-5) IOOBE（持 quickshop.tag.shops 即 100% 复现）；改移除 TOTAL 后再判空 + Pagination totalPages 下限 1（结构性防御）。
11. **tag shops 条目 null 商店**：标签索引残留已删商店 ID（清理失败仅告警）即 NPE 中止列举；补守卫跳过。
12. **/qs suggestprice 空侧中位数**：总数≥3 门可被卖店单独满足，med(空) 走 get(-1) IOOBE；统计移入各自 size>=3 条件，两个异步体补 try/catch（原异常被调度器吞、玩家停在 suggest-wait 无反馈）。
13. **/qs unlimited 全命令族缺商店级鉴权**：50 个子命令中唯一无 playerAuthorize/other.* 双门的商店变更命令——持 quickshop.unlimited（常授管理组）者可对任意商店切换无限，unlimited-shop-owner-change: true 时 migrateOwner 直接没收；新增 BuiltInShopPermission.SET_UNLIMITED（ADMINISTRATOR 组经 values() 自动获得，员工组不授=属主层级），SubCommand_Unlimited/SilentUnlimited/UnlimitedComponent 三处补双门，plugin.yml 声明 quickshop.other.unlimited 入 moderator children，语言键 en/zh。
14. **四命令幽灵玩家**（Staff/StaffAll/TaxAccount/Permission）：name2Uuid 永不失败（离线哈希兜底）、Permission 的 null 分支为死代码——打错名字把幽灵 UUID 写入权限表（StaffAll 写全部商店、TaxAccount 成静默吞税款的幽灵账户）；镜像 R54 SetOwner 的 getPlayerExact+getOfflinePlayerIfCached 双查门。
15. **/qs lookup create 空名**：`[a-zA-Z0-9_]*` 允许空串→configuration.set(空路径) IllegalArgumentException 且 stacks 已污染；正则改 +、校验前移。
16. **/qs toggledisplayall 部分应用**：遇首家无权限商店 return 中止（己方已切换他人未动）；改 continue，消息按实际生效范围（非 admin 传 server 回落自有却报 server 版消息）。
17. **/qs staffall list 首店中止**：首家无员工 return 截断后续商店列举；改 continue。
18. **/qs name 多词截断**：只取首参数，多词店名静默丢弃且照常收费；改 join 全部参数。

## 三、完好不变式抽样（本轮验证通过的）

- **交易双段提交契约**：actionBuying/actionSelling 均为先 completable() 预检→物腿（shop.buy/sell）→safeCommit 钱腿→失败 rollbackCommittedTrade 同 tick 同线程回滚物腿（第三方 trade service 仅记人工对账不自动回滚，语义正确）；无限店回滚方向（正向 trader→null 销毁 ↔ 回滚 null→trader 铸造回）与有限店 chest↔trader 对称。
- **金额守恒**：fromAmount = amount + fromTax；受益方合计 = amountAfterTax + totalTax = amount - toTaxAmt + toTaxAmt + fromTaxAmt = fromAmount，两侧闭合；无 benefit 时 owner=amountAfterTax；非正份额在 commit 循环有既存守卫（本轮发现的是反序列化绕过，已堵）。
- **建店竞态**（排除）：pending 会话按 UUID 隔离 + 聊天与建店均 regionThread(店位置) 串行 + createShop 头部 getShop(loc)!=null 双保险；手持物品变化经 SimpleInfo 构造期 clone 无害。
- **交易与删除/卸载并发**（排除）：全部删除入口（BlockListener/SubCommand_Remove/ShopPurger/OngoingFeeWatcher）与交易同 region 线程序列化；actionTrade 前重新 getShop 已删即拒；ShopPurger 只删离线属主且 executing 守卫。
- **setOwner/属主变更并发**（排除）：Paper 主线程串行；聊天路径 SimpleInfo.hasChanged 的 JSON 快照对比拦截属主/价格变动期间的旧会话；handleShopOwnerChanged 有位置表归属守卫。
- **命令面排除项**（代理逐条源码复核）：Amount 经 isNumeric+parseTradeAmount 双门、Size 有 try-catch 与上限链、Buy/Sell/Freeze/Item/Sign/ToggleDisplay/TaxAccount/Empty 鉴权与 plugin.yml 对齐、Find/Favorite/Avoid/Watch 分页钳位与 null 商店检查、Tag 其余子命令权限独立对齐、CleanGhost 有确认门、Reset 删除失败正确报错、异步命令均有 exceptionally（SuggestPrice 除外已修）、TabComplete 无泄露（Staff 用尊重 canSee 的 getPlayerList）。
- **语言文件**：en/zh 双侧 YAML 解析通过、新键结构断言（price-line×8/item-info×3/filter-indicator×3/shop×10）逐项验证。

## 四、已接受残留（带理由）

| # | 残留 | 理由 |
|---|---|---|
| 1 | registerShop 清理路径可能遗留 DATA 表孤儿行 | updateShop 按内容去重复用 data 行，孤儿行是无功能影响的垃圾数据；删除需额外 dataId 反查链路，收益小于复杂度 |
| 2 | INCLUDE_ATTACHED 位置缓存不随邻接方块变化失效（3min TTL 内陈旧） | 有 TTL 有界；影响仅限邻接保护判定延迟，无资金面 |
| 3 | SimpleCommandManager REQUIRE 权限 AND 语义（create 需同时持 cmd+sell/buy） | 功能性授权语义而非缺陷；改动属行为变更 |
| 4 | findCooldown Map 按历史玩家数增长、ToggleDisplayAll 主线程全量同步处理 | 前者有界于历史玩家数；后者为性能面（管理命令低频），非本轮安全/正确性范畴 |
| 5 | ShopListPage/GroupedItemPage 物品名为 prettifyText 枚举名（非客户端本地化物品名） | 数据面与两页既有先例一致；本地化物品名走客户端翻译是独立增强项 |
| 6 | Folia region 一致性系统性方案、AsyncChatEvent 迁移、多服务器共享 DB 竞争、实机 E2E/浸泡 | R54–R57 连续留白维持；本轮 CHM 化已消除 playerGroup/benefits 的跨线程结构损坏风险，但全量 Folia 专项仍待做 |
| 7 | matcherplus 模块无法本地解析 | R37 起留档的既有环境问题（上游仓库不可达），本轮未触及该模块 |

## 二、修复清单（五批次 60 处，全部附验证）

### 批次一：主线程阻塞与交互流畅性（35ba94d）

1. **PAPI 双 metrics 占位符主线程全表 JDBC**（PurchasesPAPI/TransactionAmountPAPI）：缓存（15 分钟 Guava）未命中时在占位符解析线程（聊天/Tab 渲染=主线程）同步执行 `queryServerPurchaseRecords(limit=-1)` 全表扫描，且 handlePlayer 对**每行**做 `QUserImpl.createSync` 名字解析（可触 DB/web）。修复：PAPISubHandler 新增 `useSoftCache()` 声明式接口；PAPICache 新增 stale-while-revalidate 软缓存（命中即返、过期返旧值+QuickExecutor 异步刷新、未命中返空待下次渲染出现，软缓存 4096 上限、reload 清空）；PAPIManager 分发前按 handler 选路。
2. **WorldListener.onWorldLoad 主线程全量加载**：WorldLoadEvent（主线程 MONITOR）同步 `loadShops`（全表三表 JOIN JDBC + `allOf().join()` 等待全部反序列化）——启动每世界一次、Multiverse 运行时加载触发，万店远程 MySQL 单次卡 1-10s。修复：事件线程仅快照 loadedChunks，加载与 map 重建入异步线程（CHM 操作），loadShop 收尾回主线程（快照与原同步行为逐位一致）。
3. **SubCommand_Recovery 显式回主线程加载**：成功/失败两分支均 `Util.mainThreadRun(loadShops)`，把导入恢复后的全表加载推回主线程。修复：去掉包裹（ShopLoader 内部自带回主线程调度），全程异步。
4. **菜单渲染主线程 flush+SELECT+join**（MarketUtils.loadInventoryCaches）：每次打开/翻页/排序/搜索浏览菜单、打开交易菜单都在主线程先冲刷写批次再等一条 `IN(...)` 查询返回。修复：3s TTL 内存快照（读窗口内纯 map 查找；过期异步刷新且保持「先 flush 待写批次」语义；冷缓存首渲染最多等 250ms 有界；查询失败负缓存 ~1s 防风暴）；SubCommand_Browse 在异步阶段预热；**顺带删除无调用方的无快照变体与 getStockFromCache/getSpaceFromCache**（主线程调用即抛 IllegalStateException 被吞恒返 0 的陷阱路径——其中 groupShopsByItem(List) 内嵌的逐店统计循环在快照路径上每次渲染仍白付一遍该陷阱）。
5. **OngoingFeeWatcher 瞬时故障删店 + 异步经济调用**：`provider().balance()` 把一切异常映射为 0，`0 < cost` 即 `removeShop` 删店——经济插件一次抖动（服务重注册窗口/超时）就永久删除玩家商店；且 balance 在异步计时器线程直呼（经济插件普遍非线程安全）。修复：周期入口 provider 无效直接跳过；删店决策改主线程二次确认（仍不足才删）。
6. **EconomyLoader 主线程 Mojang API**：税户为玩家名且 usercache 未命中时 `Bukkit.getOfflinePlayer(name)` 在主线程同步请求 Mojang API（开服后第 1 tick）。修复：getPlayerExact/getOfflinePlayerIfCached 双查（R54 SetOwner 先例），未命中移异步解析后回主线程补建账户。
7. **/qs list 主线程 15s 名字解析**（addon/list）：`name2Uuid`+`uuid2Name` 双阻塞（最长 15s，含 PlayerDB web 请求）。修复：查询整体移异步（对齐 /qs staff 先例）；页码 ≤0/负数钳制为 1（原打印「第 0 页」表头/超大页码空表）。

### 批次二：监听器语义（c16ba08）

8. **PlayerLockClickListener 无副手检查**：同一次右键主/副手事件各处理一次——that-is-locked 消息双发（lockCoolDown 只去重 bypassing-lock）；`QuickShop.inShop`（ConcurrentLinkedQueue 允许重复元素）被双重注入，而 InventoryClose/Quit 的 `remove(Object)` 每次只移除一个 → UUID 残留膨胀且被漏斗热路径线性扫描。补 `getHand()==HAND` 门。
9. **BlockListener.onBreak MONITOR 删店无鉴权（配置相关安全洞）**：生存删店分支完全依赖 shop.lock 控制的 LockListener（LOW）先行取消；`shop.lock=false` 时该监听器整体注销，**任何生存玩家（及创造无权限玩家）破坏任意他人商店箱=商店被删+success-removed-shop**。MONITOR 删店前补 DELETE 权限/other.destroy 鉴权门（lock=true 时 LockListener 已取消不会到达，无双消息）。
10. **QSEventManager.ignoredListener 并发 CME**：rescan（插件启停触发，clear+反射重建）与异步 QS 事件的 fireEvent 无锁遍历共享普通 ArrayList。改 CopyOnWriteArrayList。
11. **EconomySetupListener 死代码**：全仓库零引用，而 QuickShop.onEnable 注释宣称「有监听器兜底经济服务注册」——非 Vault 经济晚于 1-tick 延迟加载启用时无兜底。正式注册（仅 provider==null 时重试 load）。
12. PlayerListener.onDyeing 补副手门（对齐同文件 onClick 先例；取消幂等但探测与日志双跑）。
13. ChunkListener.onChunkUnload PerfMonitor 移出循环（原每店新建+拼接 Chunk.toString）。
14. ShopProtectionListener 活塞伸缩改 `getShopRedstone` 缓存查找（漏斗路径先例，缓存关闭透明回退；原每方块双哈希+attached 解析）。
15. AbstractProtectionListener/InternalListener 构造器重复注册 reloadManager（AbstractQSListener 已注册）→ reloadModule 双跑；删除冗余注册。

### 批次三：任务存活与 reload 一致性（b78c988）

16. **/qs reload off-by-one**：SubCommand_Reload 第一步 `JavaPlugin.reloadConfig()`（覆盖为 reloadConfigSubModule）时 config.yml **尚未读盘**（真正读盘在 reloadManager 链中 MainConfig.reloadModule）——第一步刷新的全部字段与 QuickShop.reloadModule 重注册的 display/lock 任务读到的都是旧值，改配置需**连续两次 reload**。修复：QuickShopBukkit.reloadConfig 先 `mainConfig().load()` 读盘。
17. **ongoing-fee reload 失效**：`registerOngoingFee()` 在 reloadModule 中被注释（enable/ticks 改动重启才生效）；且原实现 reload 路径会不停旧计时器直接替换字段（双计费）。改「先停旧再启新」并接回 reloadModule。
18. **MainConfig 双重注册**：initConfiguration 在 onLoad/onEnable 各 new MainConfig 并注册 reloadManager，旧实例永久滞留 reload 链（每次 reload 多一次无效文件 IO）。补 config==null 门。
19. **display 关闭后虚拟展示物残留**：reload 关掉 shop.display-items 时只注销保护监听器，已生成的虚拟展示物继续存在至区块卸载。registerDisplayItem 关闭分支补 `virtualDisplayItemManager.unload()`。
20. **onDisable 顺序**：logWatcher.close 在 cancelAllTasks 之前——close 后计时器仍可能触发一次 run() 对已关闭 writer 写入（丢尾日志）。先取消全部任务再 close。
21. **QSConfig.save 错误路径 IOOBE**：失败分支 `nodes.get(0)`（nodes 几乎恒空）抛 IndexOutOfBounds 掩盖真实保存失败。改 fileName。
22. **批处理周期任务无兜底**：BatchingQueue/MetricBatcher 的 timer 直接调度 `this::flushAsync`（同步段外异常即杀死周期任务且句柄未存无恢复——批处理退化为纯阈值触发）；BatchBukkitExecutor.run 的 consumer 抛出即杀死 1-tick 批任务且 callback future 永不完成（调用方悬挂）。整周期包 catch Throwable；consumer 异常 completeExceptionally+stop。

## 三、完好不变式抽样（验证未破坏）

- **主线程排除项复核**：onDisable 保存 join（15s 超时+20s 预算）非交互路径；History/SilentHistory/RemoveAll 的 join 均在 asyncThreadRun 块内；ContainerShop 主线程走内存库存分支；BukkitSkullProvider profile 更新全程异步；SimpleShopControlPanelManager 锁为微秒级 map 操作；EnvironmentChecker sleep 为有意的启动挂起；全仓库无 sleep/wait/latch/同步区块加载命中。
- **reload 链**：语言（SimpleTextManager 全缓存清空重载）、价格限制器、权限、interaction、Util、PAPICache、税管理器等 20+ 模块 reloadModule 验证会刷新；监听器 AbstractQSListener.register 幂等（先 unregisterAll）。
- **onDisable 主链**：卸载展示物先于数据保存、批队列同步冲刷先于连接池关闭、worker 池最后关闭、QuickShopBukkit 层二次兜底——顺序走查合理（仅原 logWatcher 时序已修）。
- **addon 侧 /qs reload 安全性**：simplereloadlib 只重跑主插件 Reloadable，addon onEnable 不会被 /qs reload 重复执行（与 R55 voidchest 问题不同源）；修复的注销路径针对 PlugMan 式独立启停。
- **plan/limited 计数语义**：limited 仅在 ShopSuccessPurchaseEvent 累计（失败交易不计数）、等于 limit 放行的边界、周期重置 ordinal 比较语义均复核正确；discount 折后计税与主插件经济链一致（R53 结论维持）。
- **语言与配置**：en/zh_cn 键集合双向差集为空（865 键）；config 其余 ~150 键均有消费点且行为与注释相符（含 shop-tax 四值语义、progressive ceilingEntry、-1 哨兵等）。

# R55 逻辑与稳定性审计（2026-09-17）

> 第五十五轮。视角：**数据持久层完整性（数据库读写/迁移/批写）、经济 provider 层（Vault 桥接）、展示物协议面（packetevents 后端）、compat 保护边界（residence/dominion/openinv/matcherplus 等 13 模块）、长时高负载稳定性（周期任务存活/无界增长/监听器与强引用泄漏）**。全部为 R54「本轮未覆盖」清单上的方向，与 R53（菜单并发）、R54（命令/聊天输入面+计量）互补。
>
> 方法：主审逐文件精读（SimpleDatabaseHelperV2 全文、DataTables、DbWriteBatcher、DatabaseIOUtil、VaultProvider、EconomyLoader、QSEconomyManager、ShopDataSaveWatcher、LogWatcher、ContainerShop 更新门与 setOwner、VirtualDisplayItem(Manager)、packetevents 三工厂、ChunkPacketPeek、GuiChatInputManager）+ 三个并行探查代理（展示物协议面 very thorough、compat 13 模块 very thorough、长时泄漏专项 very thorough）。**所有代理发现均回源码亲自验证后才修复**（packetevents 的 EventManager API 签名还用本地仓库 jar 反编译核对：`registerListener(PacketListener, priority)` 确实返回 `PacketListenerCommon`）。

## 二、修复清单（六批次 28 处，全部附验证）

### 批次一：交易与库存数据安全（40d39a3）

1. **openinv `EnderChestWrapper.createSnapshot()` 未克隆**：`getContents()` 返回的数组元素是末影箱的 live mirror——快照与库存同步变化，交易失败回滚时 `restoreSnapshot` 把**已扣减后的状态写回**，回滚成为空操作；末影箱商店任何一次经济后置失败（扣款失败/税账户异常等）都让店主物品凭空消失。对齐 `BukkitInventoryWrapper` 逐项 clone。
2. **`ContainerShop.setOwner()` 不重绑插件容器**：末影箱商店的 symbolLink 是建店时 owner 的 UUID，`/qs transfer` 转店后新 owner 继续从**旧 owner 的末影箱**出货并收钱（交易路径对特殊容器无所有权再校验）。修复：转移时若当前 provider 非物理容器（registry 注册名比对）则回绑商店方块处的实体容器；方块非容器/异常时保留旧链路并告警。`QuickShop` 补 `getInventoryWrapperManager()`。
3. **matcherplus `SilkSpawnerCheck` 蛋↔笼跨材质等价**：`matches()` 只比较实体 ID 字符串（zombie 蛋与存 zombie 的刷怪笼都解析为 `"zombie"`），而 `ShopItemMatchEvent.matches=true` 在核心匹配器 `QuickShopItemMatcherImpl` 中**短路后续材质门禁**——廉价刷怪蛋可稳定卖给高价收购刷怪笼的商店（及反向挂羊头卖狗肉）。补「同为蛋或同为笼」类别门。

### 批次二：长时运行稳定性（a6dd826）

4. **`ShopDataSaveWatcher.run()` 无异常保护**：`Shop::update` 在收集流内同步执行到记录快照，单店序列化异常穿出 run() → 调度器移除该周期任务 → **全服脏商店的 5 分钟自动保存自此静默停摆**（最坏数小时交易数据丢失面）。整段包 try/catch(Throwable)。
5. **`ContainerShop.update()` CAS 门锁死**：`updatingAtomic` 置 true 后 `updateShop()`（同步做 `createDataRecord()`）在调用线程抛出时 whenComplete 永不执行——该店**永久无法保存**且后续 update() 走 CAS bail-out 返回 null future 假装成功。异常路径复位 CAS 并返回异常完成的 future。
6. **`LogWatcher` 失效后无界队列**：日志文件打开失败（只读盘/磁盘满）后 printWriter 恒 null（仅构造器赋值，原「Waiting for init」注释是错的），log/logLazy 无界入队而 run() 永不消费，高频交易服数周内 OOM。printWriter 为 null 时入队前丢弃。
7. **`registerDisplayItem()` reload 叠加**：每次 /qs reload 无条件 `runTimerAsync` 新任务且句柄丢弃（旧实现仅 CUSTOM 真实物品展示模式注册），N 次 reload=N 个并行全量商店扫描。保存 WrappedTask 句柄、重注册前先 cancel（对齐 registerDisplayAutoDespawn 先例）。
8. **`DisplayAutoDespawnWatcher.run()` 无异常保护**：单店 spawn/remove 抛出即杀死展示物自动显隐任务（全服展示物冻结直到重启）。整段包 try/catch。
9. **`CalendarWatcher.run()` 同类无兜底**（日跨事件驱动持续费/清理器）。补 try/catch。

### 批次三：展示物后端（256ae7a）

10. **packetevents 三工厂注销永久空转**：`registerSendChunk/registerUnloadChunk` 注册匿名监听器但从不给 `chunkSendingPacketAdapter/chunkUnloadingPacketAdapter` 字段赋值，`unregister` 判空直接跳过——插件 disable→enable（PlugMan）后旧监听器存活叠加（每个 chunk 包双重处理）、旧匿名类钉住旧类加载器。接住 `registerListener` 返回的 `PacketListenerCommon` 存入字段（API 签名经 jar 反编译核对；protocollib 三工厂本就正确）。
11. **构造器 `load()` 造成 chunksMapping 双份引用**：构造器 put 一次 + spawn() 再 put，`List.remove` 只删一份——稳态下每个已 spawn 展示物在桶里两份，**每次区块重发对每个玩家每个展示物双份 destroy+spawn+meta+velocity**；且从未 spawn 即删除的展示物（生成事件被取消/商店未加载）因 isSpawned=false 跳过 unload 而**永久泄漏索引条目**。删除构造器 load()（索引消费方全部门控 isSpawned，构造期条目无消费者；spawn() 的 load 足够——与代码内「must move load task to first spawn」的既有注释一致）。
12. **packetSenders 跨世界幽灵**：换维度不触发旧世界 chunk 卸载包，玩家 UUID 残留在旧世界展示物的发送者集合，之后任何全量重发（物品更新/despawn 周期的 respawn）会在**新世界同坐标生成幽灵展示物**。sendFakeItemToAll 过滤非本世界玩家。
13. **PlayerChangedWorldEvent 主动清理**：manager.clearPlayer 遍历 chunksMapping 移除该玩家全部发送者条目（内存卫生，不等下次重发才清）。
14. **展示物 Reloadable 泄漏**：每个 display 构造即注册 reload 管理器但从不注销（删店/换物品各泄一条，每次 /qs reload 还会戳死对象）。新增 `AbstractDisplayItem.dispose()`（remove+unregister），`ContainerShop.setItem` 与 `SimpleShopManager.deleteShop` 接线；chunk 卸载路径（handleUnloading）保持 remove 复用语义不动。
15. **ChunkPacketPeek 防御**：readableBytes<8（截断/被前置监听器消费的缓冲）返回 null，调用方跳过，不把异常抛进 netty 管线。

### 批次四：compat 保护边界（a4ba108）

16. **dominion `ChunkBounds.max()` 用 minX/minZ**（复制粘贴错误）：min/max 构成的域退化为区块最小角一条竖线，`delete-on-lose-permission` 的 intersectWith 几乎永不命中——成员被移除/失去 PLACE 权限后商店残留他人领地。改 maxX/maxZ。
17. **domion 全部处理器无 api 门控**：`DominionAPI.getInstance()` 失败时 api=null，处理器内 NPE 被 Bukkit 吞掉后事件继续（fail-open，模块静默失效）。补 `active()` 门（enabled && api!=null；enabled 字段原为赋值后无读者的死变量）。
18. **dominion whitelist-mode 与配置注释矛盾**：注释明言「阻止在领地外**建店**或交易」但 onPreCreation 对 dominion==null 直接放行（只实现了交易半边）。补野外建店拦截 + 新语言键 `addon.dominion.creation-denied-wilderness`（en+zh_cn）。
19. **dominion deleteShopInDominion 对未加载世界 NPE**（`new ChunkBounds(null,..)` → `world.getMinHeight()`）。跳过未加载世界。
20. **residence 自定义 flag 无 owner 直通**：quickshop-create/quickshop-trade 非 Residence 内置 flag，走手写 map 查找（不含 owner 判定）——默认配置下**领地主人自己也无法在自己领地建店/交易**。playerHas 补领地 owner 放行（世界级 flag 查找传 null 不适用）。
21. **matcherplus `AdvancedItemsCheck` 字符串引用比较**：PDC 读出的 String 永不 intern，`==` 恒 false——该检查自诞生起从未放行过任何合法交易（误拒方向的功能死代码）。改 `Objects.equals`。
22. **matcherplus `PyroFishingCheck` 弱匹配**：仅比单个 int 标签，同 fishnumber 不同材质（或伪造标签的廉价物品）被判等价且绕过核心材质门禁。补材质相等门与 -1 防御。
23. **elitemobs `ShopItemEvent` 检查 `old()` 而非 `updated()`**：灵魂绑定物品可被设入商店（创建/购买有拦，无泄漏），但一旦设入即再也改不出——商店自锁。改拦 updated()。
24. **voidchest 每次 /qs reload 重复 register**（监听器成倍叠加）。补 registered 幂等门。

### 批次五：内存卫生与 API 契约（fbfc209）

25. **`shopsByOwner` 空列表残留**：unindexShop 与 handleShopOwnerChanged 只清列表内容、从不移除 map 键，每个历史 owner 永久占用一个空 CopyOnWriteArrayList（重度流转服数万级慢性泄漏）。改 `computeIfPresent` 原子「移除+空则删键」（避免 isEmpty 判断与并发 computeIfAbsent 重索引的竞态把含新店的条目误删）。
26. **SimpleShopCache 默认容器无 maximumSize**：expireAfterAccess 仅在后续维护写时驱逐，漏斗事件/菜单渲染的突发异坐标查询可在 3 分钟窗口膨胀。补 maximumSize(8192)。
27. **GuiChatInputManager 静态单例 reload 后失效**：disable→enable 后 Bukkit 已注销监听器但 registered 标志仍 true，再启用后 ensureRegistered 永久 no-op（GUI 聊天输入整体失效）且静态字段钉住旧插件对象图。getInstance 校验插件实例不符即重建。
28. **`getPlayerLocale(QUser)` 违约返回裸 null**（接口声明 @NotNull future）：非真实玩家走该分支，第三方链式调用即 NPE。改 `completedFuture(null)`（值可空、future 非空）。

## 三、完好不变式抽样（验证未破坏）

- **批写队列**：BatchingQueue/MetricBatcher 失败 reoffer + MAX_PENDING(10k) 上限 + 超限丢弃有日志 + shutdown flushSync 阻塞 drain——失败路径不丢数据（除非触顶，有 error 日志）；onDisable 顺序（metric → dbWrite → 停 watcher → 带预算兜底保存 → 清内存 → display → logWatcher.close drain → cancelAllTasks）走查合理。
- **数据库写路径缓存**：dataIdByRecord/persistedRecordByShop/dataIdByShopId 均 maximumSize(8192/16384)+expireAfterWrite(10min)，10 分钟界即多服共享库的陈旧界；bulk delete 路径（purgeIsolated）先整表失效缓存。
- **迁移链断电安全**：每步 addColumn/modifyColumn 失败仅 debug 日志（重复执行无害），版本号只在全部步骤完成后写入——中断重放幂等；schema 高于支持版本时启动即拒绝（防降级破坏）。
- **展示物并发**：chunksMapping 读写全部在 CHM bin 锁内互斥、发包刻意挪到锁外；isSpawned/pendingRemoval volatile；spawn/load/respawn 有 ensureThread 主线程断言；packetSenders 为 ConcurrentSkipListSet。
- **compat 正面验证**：clearlag 的 guard PDC 判定与主插件同源；angelchest PRE_CANCELLABLE 拦截正确且 plugin.yml 硬 depend；ecoenchants/reforges 只影响聊天预览外观不影响交易匹配；itemsadder null 安全；common 模块 onDisable 统一反注册 Bukkit 监听器。
- **经济层**：VaultProvider 服务事件重注册前 unregisterAll（防指数翻倍）、所有异常路径保守失败（balance 异常=0 → withdraw 预检拒绝）；EconomyLoader 税账户不存在时创建+警告链完整；QSEconomyManager provider 名统一大写规范。
- **玩家退出清理链**：PlayerQuitEvent 清 interactiveManager/inShop/GuiChatInput.pendingInputs + 异步写库；其余以 UUID 为键的结构（cooldowns 24h/taskCache 60s/lockCoolDown 1s/deleteConfirmation/ExpiringSet 自清扫）全部可证有界。
- **FastPlayerFinder**：handling 以 WeakReference<ExecutorService> 为键、resolver finally 必清、每小时 Timer 扫描已 GC 项、disable 时 stop。

## 四、已接受残留（带理由）

| # | 残留 | 理由 |
|---|---|---|
| 1 | chunk 包监听在 netty 线程读 `player.getWorld().getName()` 并可能触发同步 `DisplayApplicableCheckEvent` | `AbstractQSEvent.hasListeners()` 默认无监听整体跳过（默认配置安全）；把 resend 挪主线程调度是每 chunk 每玩家的任务开销，性能权衡不划算；仅当第三方注册该事件监听才暴露 |
| 2 | 虚拟展示实体 ID 从 `Integer.MAX_VALUE` 递减，与其他同技巧插件可能碰撞 | 生态惯用做法，无全局协调 API；碰撞表现为展示物互相覆盖（视觉），无数据风险 |
| 3 | `VirtualDisplayItemManager.shopEntities` 只写不读的死索引 | public 字段可能是第三方读取面；维护成本已付（spawn/remove 均维护） |
| 4 | 世界卸载后商店 Location 钉住 World 对象 | 仅动态加载/卸载世界服受影响；`setWorld(null)` 会改变 Location 键的 equals 语义破坏 shops 索引一致性（键迁移链 onWorldLoad 依赖同一对象），重构风险大于收益；世界重载时 setWorld 已恢复 |
| 5 | residence `allow-permission-override: true` 默认给领地主人圈内商店全部权限（含 ACCESS_INVENTORY/OWNERSHIP_TRANSFER） | 配置注释已声明 "full-control"，属设计如此；风险面（房客商店被领地主接管）已在此知会管理员可关闭 |
| 6 | residence/dominion 的 ShopCreateEvent 处理对 `getBukkitPlayer()` 非在线用户跳过检查（放行方向） | 建店路径玩家实际必在线（点击方块）；离线代建由 canBuild 的 BlockBreakEvent 伪造链兜底 |
| 7 | openinv `getInventory()` 每次主线程 `loadPlayer`（潜在磁盘 IO）、to-chest 分支对已消失方块 CCE、disable 不反注册 InventoryWrapperManager | 低频管理路径（/qs echest）；OpenInv 自身缓存 mitigates；反注册 API 语义未确认不乱动 |
| 8 | VaultProvider withdraw 的 balance 预检与 withdrawPlayer 之间的 TOCTOU | withdrawPlayer 是权威操作（余额不足时事务失败返回 false），预检只是省一次失败调用；无资金凭空增减路径 |
| 9 | `updateShop` 新建 dataId 分支不回填 dataIdByShopId | 下次 locateShopDataId 会 SELECT 并缓存；错过一次优化非正确性缺陷 |
| 10 | 站内信/购买日志清理非周期（仅启动+手动 /qs clean）；qs.log 文件轮转仅发生在构造时 | 既有设计；连续运行数月的 DB 体积增长由管理员定期 /qs clean 或外部维护；改为周期任务属功能增强非缺陷修复 |
| 11 | matcherplus BreweryX/CrazyCrates/ExcellentCrates 检查维持现状 | 本轮逐个验证：键要求至少一侧持有、null 方向判定正确，未发现误放行 |
| 12 | slimefun 爆破工具事件半径内含商店即整体取消 | 防护方向正确（过度取消只影响爆破工具 UX）；匹配仅作用于黑名单/限价表达式，不参与交易匹配 |
| 13 | matcherplus 模块本地编译不可验证 | 上游 crazycrew 仓库 502（R37 已留档的既有环境问题）；本轮改动（SilkSpawner/AdvancedItems/PyroFishing 三处）均为纯 Java 小改，人工复核 + 语法简单 |
| 14 | deleteShop「退款→卸载→注销」DB 删除失败无回滚 | 与 R36/R54 结论一致：跨经济/DB 分布式事务，复活商店可再删 |

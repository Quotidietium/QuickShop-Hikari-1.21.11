## 二、修复清单（四批次 24 处）

### 批次一：权限一致性（85aa56a）

1. **`quickshop.create.stack` 单复数错位**（SubCommand_Create:53）：代码检查未声明的 `stack`，plugin.yml 声明与 quickshop.player children 授予的均为 `stacks`——未注册名对非 OP 回退默认 false，被授 player 组的玩家 `/qs create <物品> <数量>` 建堆叠店永远失败（SubCommand_SuperCreate 同点位用的就是 `stacks`，佐证单数是笔误）。改查 `stacks`。
2. **18 个在用未声明节点补声明**：quickshop.inventory、avoid/avoid.list、favorite/favorite.list、watch/watch.list、other.setowner、tag 及 tag.add/delete/list/purge/shops/tagged/tagged.teleport/clear/clearall——此前仅作为 children 授予项存在（按名传播有效），独立默认值与 LuckPerms 节点提示缺失；全部 `default: op`。

### 批次二：GUI/文本/价格缺陷（bc4a191）

3. **ShopUtil.setPrice 缺 NOT_VALID 分支**：keeper GUI 价格聊天输入（BigDecimal 解析）`1e999` → double Infinity，limiter 返回 NOT_VALID 但 switch 无此 case 落穿到 `shop.setPrice(event.updated())`——无限价格入库（后续经济运算/序列化异常）。补 NOT_VALID→`not-a-number`（复用建店路径先例键）。
4. **员工/玩家选择页分页步长单行 9**（StaffSelectionPage/PlayerSelectionPage）：每页 36 条但翻页只进 9 条——页间重叠且 36×maxPages 之外尾部条目永不可达（history/browse 页同病已修的遗留）。改 `start=(page-1)*items`。
5. **历史菜单日志图标模板占位符错位**（en/zh 双侧）：Amount:{4} 显示金额、Total:{5} 显示税额、Tax:{5} 与 Total 重复。实参序 shopName,userName,itemName,amount,money,tax,net → 改 Amount:{3}/Total:{4}/Tax:{5}/Net:{6}。
6. **color-scheme 段缺失全局格式损坏**（SimpleTextManager.initTagResolvers）：段缺失/文件损坏时 tagResolvers 置空数组，而显式传参的解析器集会**替换** MiniMessage 默认集——`<yellow>/<bold>` 等全部标准标签在所有消息按字面输出。缺段时保留 `TagResolver.standard()`；顺带 getResource null 防护（原只捕 IOException）与未知 token 一次性告警（原静默白色）。
7. **gui.yml browse.grouped-item 键名 `display:` 与代码读取的 `name:` 错位**：其余全部图标用 `name:`，该条目的语言键查找永不发生（图标名不受 messages.yml 控制，恰因默认值相等而无视觉差异）。改 `name:` 并升 version 5→6（boostedyaml autoUpdate 把新键合并进旧用户文件）。
8. **gui.yml history.back 死配置**：历史菜单由 /qs history 命令打开无父菜单可返回，按钮从不渲染（backConfig 读后零引用）。删配置块与死代码行。
9. **ShopListPage 读不存在的 shop-list-sort/item-info 键**：前者恒 null 走硬编码默认且排序按钮显示名硬编码英文（Price ↑/Stock/Name 不随语言）；后者死变量。改读与 GroupedItemPage 共用的 `sort` 键（两页本就共用槽位布局）、删死变量、排序/筛选显示名改用既有 `gui.browse.sort.*/filter.*` 语言键。
10. **keeper.inventory 全菜单唯一缺键即整按钮消失**：其余按钮均有材质/slot 兜底。补 CHEST/slot22 兜底。

### 批次四：数据库故障路径加固 + 测试（403887a）

23. **getDatabaseVersion SQLException 静默短路迁移**：读取失败返回 -1 与「全新库跳过迁移」同值——DB 瞬断窗口下老 schema 库被当作已是最新、全部待执行迁移静默跳过、服务端带缺列 schema 运行。改抛 IllegalStateException（→bootError 启动失败明示重试）；无版本行（真全新库）仍 -1 不变。
24. **BatchingQueue.reoffer 丢弃方向颠倒**：达 MAX_PENDING 上限时丢的是刚失败批的尾部（最新值）、保留 pending 更旧值——对 last-write-wins 库存缓存是 DB 落后旧值的错误方向，对离线消息丢的是最近通知。改 oldest-lossy：从 pending 队头驱逐最旧腾位，单批自身超上限且队空才丢剩余。

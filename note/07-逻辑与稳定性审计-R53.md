> 本轮为 R38–R52 十五轮性能改动（`fb785e159..HEAD`）的首次安全/逻辑回归审计 + 全菜单并发正确性专项。
> 审计基线 `e40006d40`，收尾 `1bd2b6ea4`。威胁模型不变：修改版客户端任意输入、200+ 在线玩家高频点击、周级不间断运行。

## 审计方法

- 范围圈定：R36 安全审计（2026-08-29）之后，R38–R52 性能循环又改写了交易、经济、库存、菜单、监听器、文本六条热路径共 57 文件 +5112 行——这些等价变换（防御克隆移除、活引用探针、事件构造门控、快照化）从未经过安全审计，为本轮主靶。
- 每个代理发现都回到源码与字节码逐一验证：TNML 1.6.0.0-SNAPSHOT-15 的 Page/PlayerInstancePage/Menu/点击监听器经 javap 反汇编 + 上游 GitHub 源码双重核实；adventure 4.16 的 replaceText 递归域经字节码核实；MiniMessage show_entity 标签经本地 4.12/4.16 双版本探针证实根本不解析。
- 证伪 1 项：代理报告「Util 配置快照 /qs reload 不刷新」——实际 `Util.initialize()` 已自注册 reload manager（Util.java:1336-1338），reload 链会刷新快照，非缺陷。

## 已修复缺陷（按严重度）

### 1.【高】TNML 菜单共享 Page 跨玩家串扰（全部六处页面）`eec89880c`
原生 `Page.icons` 是全体 viewers 共享的单一 Map，而所有图标动作闭包捕获**渲染时**的 player/shop/列表。并发打开下**后开者的图标解析先开者的点击**：
- 浏览列表传送按钮把点击者传送到**别人列表**里的商店坐标（ShopListPage）；
- 交易菜单数量按钮以**最后开者身份**执行买卖（trade/MainPage，资金路径）；
- 员工页对最后开者的商店增删员工；keeper 页改价/冻结/换模式/删店同理。
且随附 TNML 库自身两缺陷（字节码+上游源码核实）：`PlayerInstancePage.addIcon(UUID,Icon)` 每次用仅含最新图标的新实例**覆盖**旧实例；点击分发链 `BukkitInventoryClickListener→Menu.onClick→Page.onClick` **只查共享 Map**（`onClick(UUID,…)` 重载全库无调用，仅渲染 build 走按玩家实例）。
**修复**：新增 `QuickShopPlayerPage`（修复累积语义 + 重写 `onClick(MenuClickHandler)` 按点击者实例解析 + `clearInstance` 关闭清理）；browse×2/trade/staff×2/history/keeper 全部页面与处理器转换；`SubCommand_Browse` 打开回主线程（构建读玩家世界且与主线程点击解析竞争共享 Map）；重建 viewer 前先 removeViewer（`addViewer` 仅合并标量不合并 data map）。顺带修复 history/MainPage **第四处**分页重叠缺陷（start 按单行 9 推进而每页 45 项→页间重叠 36 条、尾部记录不可达；R23 修过三处同病，此处遗漏）。

### 2.【高】分页 footer 按钮执行含私用区字符的坏命令 `fbe906e6e`
`PreParsedTemplate.containsSentinel` 只查文本内容/hover 组件值/children：占位符落在 `<click:run_command:"{0}">` 的字符串事件值、`<insert>` 值、可译组件 Component 参数与 show_entity 名字组件时哨兵不可见——模板被误冻结为可用。内置语言包 `pagination.footer`（messages.yml:146，zh_cn:112）的 {0}/{3} 即命令本体，上一页/下一页按钮实际执行含 `\uE400` 的命令而失效（R19 预解析引入以来既有，R45 编译模型固化）。扫描域补齐四类位置后此类模板正确判 BROKEN 走 legacy 字符串路径（先替换后解析）。`MsgUtil.containsOpenBrace` 同步补 show_entity 名字域（replaceText 会渲染该域）。tag 系列列表（`tag.list-entry`/`shops-entry`/`entry`/`list-tag-shop-entry-tp`）的 click 内占位符同批获救。

### 3.【高】SignUpdateWatcher 预算边界永久卡死 `755c3423d`
旧循环先 poll 后查时间预算：预算耗尽时已出队条目既不处理也不从 `pendingShops` 移除→该商店此后每次 schedule 都被去重门拦下，**木牌更新永久停摆直至重启**（高频交易/漏斗供料下每周期预算耗尽即丢一店）。预算检查移到 poll 之前。

### 4.【中】encode memo TOCTOU + 跨线程可见性（R42 引入）`53df16fc1`
`encodedItemForSave` 键读 `this.item` 快照后却编码 `getItem()`（重读字段再克隆）：异步冲刷线程与主线程 `setItem` 在两读之间交错时 memo 被永久污染为「旧键×新编码」，**此后每次保存持续把错误物品写入数据库**直至下次 setItem；`encodedOriginalItemForSave` 同病。改为编码所键快照本体（setItem 为替换引用式更新，旧栈无人可再突变）；六个 memo 字段补 volatile（跨冲刷线程无 happens-before，撕裂组合可持久化陈旧编码）。

### 5.【中】脏标记丢更新守卫（基线即有的结构性问题）`8b4bf5538`
`updateShop` 调用时同步快照保存记录、SQL 异步完成，完成回调无条件清零 dirty：快照与写库完成之间落地的任何 `setDirty` 既不在记录里、dirty 又被清零，**变更静默丢失持久化**直至下次碰巧的 setDirty。新增 volatile `dirtyGeneration` 世代计数：setDirty 自增、update 快照前捕获、完成回调仅世代未推进时清 dirty；顺带兜底 CAS/inFlightUpdate 赋值间隙的假完成信号。

### 6.【低】buyFromShop 无货早退零刷新 + matchesSearch 防护 `1bd2b6ea4`
R51 渲染去重跳过显式 setSignText 后，无监听器路径唯一刷新点 onClick 位于库存门之后→无货点击整链零刷新。早退分支补一次 onClick。matchesSearch 单次 getItemMeta 补 null 防护（与 MarketItemGroup 既有防护对齐）。

## 已知残留（评估后接受）

| 项 | 说明 | 理由 |
|---|---|---|
| `hasListeners()` 生产恒真 | InternalListener（QuickShop 无条件注册）监听 6 类 QS 事件，全部 QS 事件共享 AbstractQSEvent 的单一 HandlerList→R46/R50/R52 的事件构造门在生产**永不生效**（安全方向：恒走慢路径=历史行为） | InternalListener 自身会取消建店（shulker 门）与购买（禁售门），门控必须保守；重构 HandlerList 为每事件独立属 API 破坏性变更，留待专项 |
| 面板单 items 快照（sendShopInfo） | 监听器在面板事件中 setItem 后，后续行显示旧物品 | 仅第三方主动改物品的监听器可见；每行重取即回退 R51 优化 |
| 税腿入账失败 soft-fail | 税额销毁、交易记成功 | R36 已接受（有日志）；Vault boolean 契约同源 |
| 回滚失败 op 仍列入已回滚清单 | API javadoc 与行为不符 | safeCommit 忽略返回值，无内部影响 |
| shopId=-1 并发删除碰撞 | 两个未持久化商店并发 deleteShop 时第二个静默跳过 | processCreationFail 自行补 unload；窗口极窄 |

| R34 addItem 完全契合分支不调 setItem | 开箱观察者可能短暂幽灵显示 | 镜像为活引用服务器状态一致；客户端包由后续交互刷新 |

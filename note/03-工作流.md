## 2. 交易执行流程

```
行为触发（TradeDirect 一组 / TradeDirectAll 全部 / TradeUI 菜单 / 聊天数量）
├── actionTrade 解析数量：数字 n 或 "all"
│   └── all: buying 店按店主余额封顶(buyingShopAllCalc)；selling 店按库存/背包空间封顶
├── 分发：SELLING 店→actionSelling（买家买走）；BUYING 店→actionBuying（买家卖出）
├── 权限链：quickshop.other.use（非自营）/ BuiltInShopPermission.PURCHASE（店主授权）/ 自交易拒绝
├── shopIsNotValid 一致性检查（provider 失效/容器空/Info 过期）
├── 算税（ShopEnhancedTaxEvent 可调）→ ShopPurchaseEvent（可取消可改价）
├── 库存过户 failSafeCommit ─失败→ 自动 LIFO 回滚，交易终止（钱未动）
├── 经济 safeCommit ─失败→ 反向补偿（⚠库存已过户，见 02 笔记权衡）
└── 成功 → 收据 + ShopSuccessPurchaseEvent → 指标写库(异步) + 店主离线消息(qs_messages, 7 天过期)
```

## 3. 商店删除流程

触发源（5 个）：`/qs remove` / 容器被破坏(BlockListener) / OngoingFee 余额不足 / ShopPurger 定期清理 / 加载期坏商店。

```
deleteShop (SimpleShopManager.java:1346)

├── 遍历告示牌方块置 AIR
```

## 4. 配置热重载

`/qs reload` → simplereloadlib ReloadManager → 逐个回调 Reloadable 组件（MainConfig/GuiConfig/InteractionConfig/全部监听器/TextManager）→ 广播 `QSConfigurationReloadEvent` → 所有 CompatibilityModule 自动 reloadConfig + init()。

## 5. CI/CD（GitHub Actions，7 工作流）

| 工作流 | 触发 | 作用 |
|---|---|---|
| maven.yml | push/PR 到 hikari、cleanup | JDK21 `mvn package -T 1.5C -P github`（排除 itemsadder，其依赖无仓库）；Codecov 步骤实际无数据 |
| code_quality.yml | PR | Qodana 静态扫描 |
| intellij_style.yml | PR | IDEA 格式化机器人自动提交 |
| javadoc.yml | push hikari | 发布 Javadoc 到 gh-pages |
| mc-publish.yml | **release published** | 构建 → mc-publish 到 Modrinth + GitHub Discussion（主 jar + 全部 compat/addon jar）→ Maven 依赖图 → 翻译产物传 Bunny CDN → CloudFlare 清缓存 |
| sync-crowdinota.yml | 手动 | Crowdin→CDN 翻译同步 |
| stale_issues.yml | 每日 cron | waiting-reply 14 天 stale、30 天关闭 |

**翻译生产线（独立于发版）**：Crowdin 社区翻译(44+ 语言) → CI 推 Bunny CDN → 服务器运行时 OTA 拉取（config `use-crowdin-ota`，host=qshikari.b-cdn.net）。

**PR 合入链**：Qodana + Maven CI + 格式化机器人 + CodeRabbit → 人工 review → Mergify 自动合并。

## 6. 数据库维护工作流

- 自动：启动备份（CSV→zip）/ 迁移前 fastBackup / 5 分钟脏店落库 / 7 天过期离线消息清理 / purgeIsolated 孤立数据兜底。

## 7. 测试现状

**全仓库 0 个测试**。质量保障 = Qodana 静态扫描 + CodeRabbit AI 审查 + 人工 review + 社区实测。对资金敏感路径（QSEconomyTransaction / SimpleInventoryTransaction / SimpleShopManager）无任何回归网——这是本 fork 最值得补的短板。项目已依赖 H2，可用 H2(MODE=MYSQL) 内存库直接做 DAO 层集成测试。

## 8. 工作流共性设计（改代码时保持一致）

1. **所有资金路径统一走 safeCommit/failSafeCommit**，绝不直接调 EconomyProvider。
2. **所有创建/删除先发 PRE 可取消事件**，成功后发 POST。
3. **所有删除防重入**（inDeletion 队列模式）。
4. **方块操作必须经 FoliaLib 调度到区域线程**。

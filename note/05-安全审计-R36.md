### 交易完整性（批次 2）
- **经济腿失败无补偿**：`actionSelling/actionBuying` 中物品腿已提交而 `safeCommit` 失败时原先直接返回（白拿/白丢物品）。现同 tick 构造反向 `SimpleInventoryTransaction` 回滚；第三方 TradeService 仅记 `TRADE RECONCILIATION` 日志不盲目回滚；非无限商店箱子解析失败同样走对账日志（不构造单边交易）。
- **牌子更新异常误报交易失败**：`SimpleTradeService.updateTradeSign` 在物品提交后抛异常会落入 catch 返回失败、跳过金流。现吞掉并记录。
- `getPlayerCanSell` 零价除法（Infinity/NaN）防护；skull 匹配器 `player2` 误读 `skullMeta1`（任意头颅互配）；`getInventory()` 永假死分支清理（瞬态解析失败不再误删/漏卸载，行为=仅记审计日志）；交易菜单补 125ms 每玩家冷却（GUI 点击绕过交互事件限流，防点击包洪泛放大全量预览+提交）。

### 并发与内存（批次 3）
- `insertMetricRecords` HashMap 跨 DB 虚拟线程并发写 → ConcurrentHashMap + 独立去重集（CHM 不收 null 占位，见批次 7 的 null 过滤）。
- `isSpawned`/`pendingRemoval` 补 volatile（Netty 包监视线程读主线程写）。
- `shopEntities`/`chunksMapping` 空列表泄漏（spawn 回填 + remove 清理）。
- OngoingFee/SignUpdate watcher 的 async `run()` 全量 try-catch（未捕获异常静默杀死 CraftAsyncTask，功能停摆至重启）。
- ShopPurger：CAS 守卫 + finally 释放 + 虚拟主 `return→continue`（原一个非真实玩家店主即永久卡死 purge）。
- `deleteShop` 重入守卫原子化 + finally 释放（双并发删除双重退款 / 异常滞留守卫）。
- `ContainerShop.update()` 先发布 inFlightUpdate 再挂回调；跨线程读状态字段 volatile；死字段 `updating` 移除。
- BukkitSkullProvider 返回克隆（缓存模板不再被菜单污染）；UpdateManager 缓存 volatile。

### 数据库层（批次 4）
- 四个 tag 查询缺 `while(set.next())`（功能整体失效并伪装成 DB 错误）。
- `MetricQuery.queryTransactions` 读不存在的 `tax_currency` 列 + limit 参数被硬编码 1000 覆盖。
- `/qs history global` 全量加载 log_purchase（OOM/卡顿，可达即触发）→ LIMIT 1000 + distinct dataId 去重。
- **批处理队列失败丢数据**：BatchingQueue/MetricBatcher 刷盘失败改重排队（不静默重触发），上限 10000 条防 OOM，超限丢弃+error 告警。
- 关机同步保存回退加 20s 总预算（原 15s×N 悬挂）。
- ShopLoader 损坏 NBT 解码异常不再逃逸（原绕过 delete-corrupt-shops 永世重试）。

### 生命周期（批次 5）
- **LogWatcher 重载泄漏**：旧实例 PrintWriter+任务泄漏、新实例从不 start（日志队列无界+重载后全丢）→ 安全换新+start 幂等+onLoad/onEnable 双构造消除。
- Vault/VaultUnlocked 经济服务事件重复注册（处理函数指数翻倍）→ 注销后注册。

- `CommonUtil.isUUID` 补十六进制校验。
- 聊天路径交易调度改按商店 region（Folia 下与漏斗/牌子同 region 序列化，菜单路径本就如此）。
- `/qs find` 冷却表 24h 自动驱逐。

## 复审确认的关键不变式

- 回滚方向：`sell`(购买) 回滚 trader→chest（无限服 trader→null 销毁）；`buy`(出售) 回滚 chest→trader（无限服 null→trader 重建）；数量 = `unitSize*amount` 与 `normalizeAmount` 完全一致。
- EVERYONE 组含 SEARCH → 普通玩家 browse 行为不变，仅被 block/撤销者被过滤。
- `handleChat` get→remove 竞态良性（region lambda 内 remove 幂等去重保留）。
- 关机顺序：batcher flush → 商店保存 → EasySQL → QuickExecutor.shutdownAll（其后无提交）。

## 已知残留（评估后接受）

| 项 | 理由 |
|---|---|
| Folia 下 `getInventory()` 无 isOwnedByCurrentRegion 守卫 | 主路径已按商店 region 调度；Paper（主支持平台）单主线程不受影响；补守卫需异步重设计，风险大于收益 |
| 税款入账失败仅回调不重试 | 设计取舍，已有日志 |
| YAML 配置非原子写（items-lookup 等） | 崩溃窗口极小、低频写；group.yml 已有恢复机制 |
| DB 长时间不可用时 offer 触发的重试日志随交易频率刷屏 | 有 10000 上限兜底；可后续按频率限流 |
| 备份 zip 直写最终文件、importTables 无事务 | 无活动调用方/管理员手动操作 |
